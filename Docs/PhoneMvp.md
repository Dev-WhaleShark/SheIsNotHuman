# 핸드폰 MVP

기존 `OrderDocument`를 안드로이드 계열 홈 화면과 앱 두 개를 갖춘 게임 내 핸드폰으로 확장했다. 실제 휴대폰 OS나 외부 서비스에 연결하지 않는 프로토타입이다.

## 사용 흐름

현재 플레이 씬은 `Assets/SheIsNotHuman/Scenes/PerspectiveCubeViewPrototype.unity`다. 방문자의 대사를 진행하고 서류 전달이 끝나면 책상의 핸드폰을 눌러 검사 화면을 연다. 확대된 핸드폰에서 앱 아이콘을 누른다.

- **윗치폼**: 현재 방문자의 주문자, 코드, 주문번호, 상품, 수량을 표시한다. 기존 주문서 데이터와 검사 규칙을 사용한다.
- **X**: 미리 작성된 게임 내 게시물을 세로로 스크롤한다. 실제 X 계정이나 네트워크를 사용하지 않는다.
- **홈 / 뒤로**: 앱에서 홈 화면으로 돌아간다. 기존 검사 닫기 기능으로 핸드폰을 책상에 돌려놓는다.

메신저, 로그인, 결제, 선입금 처리, 게시물 작성은 이번 범위에 포함하지 않는다. 상단 시간과 통신·배터리 표시는 프로토타입 장식이며 실제 기기 상태를 나타내지 않는다.

## 코드와 에셋

`OrderDocumentView`는 주문 데이터 바인딩, 앱 전환, 확대 상태에서의 입력을 담당한다. `InspectionMvpView`는 검사 흐름과 전환 상태에 따라 핸드폰 입력을 허용한다. 앱 안에서 입력할 때 책상 문서의 포인터 처리가 함께 실행되지 않도록 입력 경계를 유지한다.

화면은 `Assets/SheIsNotHuman/Prefabs/OrderDocument.prefab`에 있다. `InspectionPhoneMigration`은 기존 주문서 프리팹에 화면을 구성하는 Editor 도구다. 기존 문서 연결과 GUID를 유지하며, 변경 전에 저장 상태와 생성 대상 에셋을 확인해야 한다. 일반 플레이에는 이 도구를 실행할 필요가 없다.

## 검증 기록

주요 직접 작성 코드의 독립 리뷰는 `gpt-6-astra` / `xhigh`로 실행했다. 세션 기록의 모델·추론 수준을 별도로 확인했으며, 증거는 `tmp/phone-validation-20260929/review-model-evidence.json`에 있다. 리뷰 범위는 핸드폰 UI, 검사 진행과 표현 계층, 문서 입력, CubeScreen 전환·좌표 처리다.

통합 검사와 리뷰 수정 결과는 아래와 같다. 자동 테스트 발견 수와 실제 Play Mode 동작 검사는 별도로 집계한다.

리뷰에서 발견한 세 가지 P2 항목은 모두 Flow/View 수명주기 계약에 관한 것이다.

1. 별도 GameObject의 View가 꺼질 때 진행의 취소와 재개가 누락되는 경로.
2. `Configure`로 화면을 교체한 뒤 이전 View의 연결이 남아 새 진행을 중단하는 경로.
3. View가 비활성화된 동안 `Restart`가 진행을 다시 시작하는 경로.

기본 씬에서 먼저 재현한 전환 잠금 문제와 함께 수정했다. 현재 연결된 화면만 진행 컨트롤러에 수명주기를 통지하고, 화면 교체 시 이전 입력 연결을 해제한다. 비활성 화면에서는 진행을 시작하지 않고 활성화를 기다린다. 사용 중인 화면을 비활성화한 뒤 다시 켜면 검사 흐름은 첫 방문자부터 재시작한다.

수정 이유와 실행 소유권은 `InspectionPresentation`, `InspectionFlowController`, `InspectionMvpView`의 계약·수명주기 주석에 기록했다. Play Mode에서 별도 View 오브젝트의 비활성화·재활성화, 화면 A→B 교체 후 A 토글, 비활성 View에서 `Restart`를 각각 확인했다.

수정본 재검토에서 A→B→A 재연결 시 위치 원점을 다시 저장하는 회귀도 발견했다. 최초 원점 캡처 여부를 입력 연결 여부와 분리했고, NPC·문서·대사의 위치를 임시로 옮긴 뒤 재연결해 세 원점이 정확히 복원되는 것을 확인했다.

| 검사 | 결과 |
| --- | --- |
| Astra 최종 수정본 재검토 | 추가 확정 결함 없음. 정적 검토이며 Editor 실행 결과와 구분 |
| Unity 명시 재컴파일 | 완료, 컴파일 오류 없음. 새 메서드 로드도 확인 |
| 앱 입력 | `EventSystem.RaycastAll`과 PointerDown/Up/Click 경로로 윗치폼·홈·X 전환 확인 |
| X 피드 | 게시물 5개, 콘텐츠 560 / 뷰포트 300. 스크롤 약 1.0→0.459, 핸드폰 위치 불변 |
| 닫기·재열기 | `Documents` 부모, 위치 `(210,-20)`, 배율 `0.55`로 복원. 다시 연 피드는 상단 |
| 수명주기 | 전환·전달 중 View 비활성화, 전체 GO 토글, 별도 GO, 화면 교체, 비활성 중 Restart 회귀 확인 |
| 위치 보존 | A→B→A 재연결 후 NPC·문서·대사 원점 3개 복원 |
| 방문자 진행 | 3명 주문 필드 갱신, PASS→NON PASS→PASS, 처리 3명 후 Completed. 재시작 후 NPC_01·처리 0명 복귀 |
| 독립 검사 규칙 | 기존 규칙 검사 15/15 통과 |
| 시각 확인 | 1280×720 홈·윗치폼·X 캡처에서 한글 렌더링과 배치 확인 |
| 자동 테스트 발견 | NUnit 테스트 0개. 자동 회귀 테스트 범위의 공백으로 기록 |
| 최종 Editor 상태 | Play 종료, 원본 씬 dirty=false, 컴파일 실패 없음. 실제 Console 오류·경고 0 |

이 검사는 Editor Play Mode의 EventSystem 입력과 API 호출을 사용했다. OS 마우스 조작, 독립 플레이어 빌드, 여러 해상도의 전체 시각 검사는 이번에 실행하지 않았다. 증거 파일은 `tmp/phone-validation-20260929/`에 있다.

Pipeline 누적 기록에는 이전 Inspector 예외 1건과 Play Mode 진입 직후 도구 응답 timeout 2건이 남아 있다. 이는 최종 실제 Console 집계(`groundTruth`: 오류 0·경고 0)와 분리했다. 최초 외부 소스 수정이 자동으로 가져와지지 않은 검사도 수정 후 통과로 계산하지 않았으며, 명시적 재컴파일과 새 코드 로드 확인 후 다시 검사했다.
